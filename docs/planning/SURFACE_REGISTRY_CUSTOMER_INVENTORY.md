### Cross-cutting notes

- `api_desktop.py:495–496` performs a `view` preflight for all routes except `PUT` without suffix; destructive operations then additionally require `_exigir_admin` before calling the locked writer (`516–528`). This is not itself the writer's authority.
- `portal_prestador.py:4433–4436` passes the deactivate request to `portal_v9.post`; `portal_v9.py:411–416` derives a `Principal` from the authenticated provider session, while `cadastros_v9.desativar_cliente` authorizes from the database inside the write transaction.
- Destructive writers **do not trust** `principal.role` or `autor` for authorization and history: `require_admin_locked` verifies `prestadores` active/non-excluded and `v9_admin_prestadores` against the caller's locked connection (`work_item_access.py:65–86`). The previous `pid=0` audit issue in `LocalService.excluir_cliente` is addressed.
- `customer.delete` and `customer.password` are **not** policy.yaml permissions. **Do not add these keys in Phase 0A**. Wildcard admin permission is not a substitute for documenting the missing explicit key.
- Part 1 confirmed GTK remote admin sessions with empty permissions still see the destructive control. `test_p0_customer_destructive_a5b2.py:261–281` exercises the actual renderer (with stubs). The pure-action-list extraction remains a separate later improvement.
- Statuses describe **current rule parity**, not test/production deployment promises. Use `known_gap` when an important route, guard, or surface parity is missing; `implemented_not_deployed` means relevant scoped implementation exists in the integration branch but is not claimed shipped to MAIN.
